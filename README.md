# CloudDrop

**CloudDrop** is a secure cloud file storage platform built with React, Node.js, PostgreSQL, Docker, Terraform, and AWS.

It allows users to upload, organize, search, download, and temporarily share files while choosing between two storage models:

- **CloudDrop Managed Storage** — files are stored securely in CloudDrop-managed Amazon S3.
- **Connect My AWS** — users connect their own AWS account through cross-account IAM roles, AWS STS, and External IDs without providing permanent AWS access keys.

CloudDrop was designed and developed as a Cloud/DevOps capstone project by **Nwachukwu Ifeanyi Divine**.

## Storage Options

### CloudDrop Managed Storage

Managed Storage is the easiest option.

Users can start uploading files immediately without configuring an AWS account.

CloudDrop securely stores the files in its managed Amazon S3 infrastructure.

### Connect My AWS

Advanced users can connect their own AWS account and store files inside their own S3 buckets.

CloudDrop does not require customer AWS access keys.

Instead, CloudDrop uses:

- IAM Roles
- AWS STS
- External IDs
- Temporary credentials

This allows secure cross-account access.

## How to Connect Your AWS Account

1. Register or sign in to CloudDrop.
2. Open **Connect My AWS**.
3. Start the AWS connection setup.
4. Copy the:
   - CloudDrop AWS Principal ARN
   - External ID generated by CloudDrop
5. Sign in to your AWS account.
6. Open:

```text
AWS Console → IAM → Roles → Create Role
```

7. Create a role such as:

```text
CloudDropAccessRole
```

8. Configure the role trust relationship so CloudDrop can assume it.

Example:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": {
        "AWS": "<CLOUDDROP_PRINCIPAL_ARN>"
      },
      "Action": "sts:AssumeRole",
      "Condition": {
        "StringEquals": {
          "sts:ExternalId": "<CLOUDDROP_EXTERNAL_ID>"
        }
      }
    }
  ]
}
```

Replace:

- `<CLOUDDROP_PRINCIPAL_ARN>` with the ARN shown by CloudDrop.
- `<CLOUDDROP_EXTERNAL_ID>` with the External ID generated by CloudDrop.

9. Attach S3 permissions for the bucket CloudDrop should access.

Example:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:ListBucket",
        "s3:GetBucketLocation"
      ],
      "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME"
    },
    {
      "Effect": "Allow",
      "Action": [
        "s3:GetObject",
        "s3:PutObject",
        "s3:DeleteObject"
      ],
      "Resource": "arn:aws:s3:::YOUR-BUCKET-NAME/*"
    }
  ]
}
```

10. Copy the AWS Role ARN.

Example:

```text
arn:aws:iam::123456789012:role/CloudDropAccessRole
```

11. Return to CloudDrop and enter the Role ARN.
12. Verify the connection.
13. Register or manage your S3 buckets and begin storing files.

CloudDrop uses AWS STS temporary credentials and does not store permanent customer AWS access keys.

## Using CloudDrop

### Register

Create an account using:

- Full name
- Email address
- Password

After registration, choose either:

- **Managed Storage**
- **Connect My AWS**

### Upload

From the dashboard:

```text
Upload File
```

Select a supported file and CloudDrop will store it in the active storage backend.

### Search and Filter

Files can be searched by name and filtered by category.

### Download

Open a file and select:

```text
Download
```

### Share

Open a file and use the **Temporary Sharing** section.

Choose an expiration period and create a link.

Example:

```text
https://13.63.134.180/api/share/<temporary-token>/download
```

Recipients can download the shared file without signing in.

### Delete

Users can delete files they own from the file details interface.

## Security

CloudDrop was designed with security in mind.

Production includes:

- HTTPS encryption
- Private RDS networking
- TLS-secured PostgreSQL connections
- Private S3 buckets
- IAM role-based AWS access
- AWS STS temporary credentials
- External ID protection
- JWT authentication
- No public database port
- No public backend port
- No public SSH port
- AWS Systems Manager administration
- AWS Secrets Manager integration
- S3 public access blocking
- Least-privilege security groups

Customer AWS access keys are not required or stored.

## Terraform

AWS infrastructure is managed using Terraform.

Terraform files are located in:

```text
infrastructure/terraform/
```

Terraform provisions resources including:

- VPC
- Public application subnet
- Private database subnets
- EC2
- Elastic IP
- Security Groups
- RDS PostgreSQL
- S3
- IAM roles
- IAM instance profile
- Secrets Manager permissions
- Systems Manager permissions

Basic Terraform workflow:

```bash
cd infrastructure/terraform

terraform init
terraform validate
terraform plan
terraform apply
```

Production Terraform state is stored remotely in Amazon S3.
